## Security

- [x] **P0 deny 不可绕过**：L2 块位于 grant 之前 + 直接 return，无 grant/配置声明/记忆通道可达。`isConfigWritePath` 对 `resolvedAbs` 与 `canonicalPath` **双查**(`:1135-1144`)，symlink/realpath 变体不被绕过。
- [x] **P0 大小写变体**：`scanBashProtectedPaths` 对不可靠 bash 命中前做 case-fold(`:545/:549`，`TRUSTED.JSON`/`PERMISSION.JSON` 仍拦)；可靠 bash 走 `decideTarget` realpath 双查。
- [x] **P0 bash 重定向写 permission.json 被拦**：不可靠 bash 经 `scanBashProtectedPaths`（含 env 展开 `$HOME/$PWD`、token 尾 `)`/`;` 剥离 subshell 写目标）→ deny_hard；可靠 bash 经 `decideTarget` per-target deny_hard。两路均硬拒，无静默放行。
- [x] **P1 `!` 不作用于 hard 敏感**：deny-path 在 sensitive 兜底分支之前(`:130` vs 后续 sensitive 分支)，`!` 只影响 `resolveDenyPath`，`sensitive.ts` hard 保护路径不经此判定，不削弱硬基线。
- [x] **globDenyToRegExp 转义完整 + 无 ReDoS**：转义集 `/[.+^${}()|[\]\\?]/`(`:294`) 覆盖全部 regex metachar（`*` 由 glob 分支独占处理，不泄漏为字面量）；`**`→`(?:.*/)?`/`.*`、`*`→`[^/]*`，无嵌套量词，线性回溯，无灾难性 ReDoS。
- [x] **deny-path 的 symlink 场景**：`decide()` step 0.5 单次按字面 absPath 判定，但上游 `handleFileTool`(`:977-982`) 与可靠 bash(`:888-897`) 都对「字面 + realpath」各调一次 `decideTarget` 取 severity 更严者，故 symlink 指向 deny 命中文件时 realpath 那次会命中 deny_hard。覆盖成立。
