## Security

- [x] **`!` 不作用于 hard 敏感**：deny-path 在 sensitive 兜底分支之前(`decision.ts:130` vs 后续 sensitive 分支)，`!` 只影响 `resolveDenyPath`，`sensitive.ts` hard 保护路径不经此判定，不削弱硬基线。
- [x] **globDenyToRegExp 转义完整 + 无 ReDoS**：转义集 `/[.+^${}()|[\]\\?]/`(`path-utils.ts:294`) 覆盖全部 regex metachar（`*` 由 glob 分支独占处理，不泄漏为字面量）；`**`→`(?:.*/)?`/`.*`、`*`→`[^/]*`，无嵌套量词，线性回溯，无灾难性 ReDoS。
- [x] **deny-path 的 symlink 场景**：`decide()` step 0.5 单次按字面 absPath 判定，但上游 `handleFileTool`(`extensions/index.ts:977-982`) 与可靠 bash(`:888-897`) 都对「字面 + realpath」各调一次 `decideTarget` 取 severity 更严者，故 symlink 指向 deny 命中文件时 realpath 那次会命中 deny_hard。覆盖成立。
- [x] **相对 pattern 不泄漏到 projectRoot 外**：`rootPrefix=""` 机制确保 absPath 在 root 外时相对 pattern 不匹配。
